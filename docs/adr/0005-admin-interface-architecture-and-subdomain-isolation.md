# Admin Interface Architecture, Subdomain Isolation, and Monorepo Integration

Administrative operations, property management system (PMS) workflows, and reservation troubleshooting are centralized within a dedicated administrative application located in an `admin/` directory monorepo served from an isolated subdomain (`admin.oceanviewflats.com`). While the guest-facing public site utilizes static site generation (SSG) with client-side vanilla JavaScript islands, the admin application utilizes a server-driven architecture powered by a lightweight PHP 8.3 front-controller (`admin/public/index.php`), pure server-rendered PHP templates, HTMX for responsive in-place DOM updates, and Tailwind CSS. 

To eliminate business logic duplication and schema drift, the admin application directly consumes the shared PSR-4 domain models in `src/Domain/` (`ReservationLedger`, `QuoteEngine`, `DoorCodeGenerator`) and shares MySQL connection credentials (`DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`). Administrative access is protected by an isolated session cookie security perimeter (`admin_users` table with Argon2id password hashing, HTTP-only secure cookies scoped to the subdomain, brute-force rate-limiting, and HTMX CSRF validation) alongside an immutable audit trail (`admin_audit_logs`). Database schema changes remain strictly centralized under `scripts/schema.sql` and deployed via CLI migrations (`scripts/migrate.php`), while an independent GitHub Actions workflow (`.github/workflows/admin-ci.yml`) validates the admin toolchain without coupling deployments to the public static build.
